## Le trou
Dans une partie en monde vivant (`m.mondeVivant===true`, `m.orgs[id]` = les sept autres organisations, chacune une partie complète avec son `roster`), `mgmtFicheLigne(m,id)` (`mgmt-ecran-fiche.js` ~ligne 31) ne cherche que le roster de `m` et `m.exterieur` : un combattant d'une autre organisation vivante est lu comme « Combattant », sans organisation (classements, fiche, lendemain, dossiers).

## Ce que tu fais
1. `mgmtFicheLigne` : si le combattant n'est ni dans `m.roster` ni dans `m.exterieur` et que le monde est vivant, le chercher dans `m.orgs[orgId].roster` (`mgmtMondeVivantIds(m)` donne les identifiants, dans l'ordre) et rendre `{f:<copie de la ligne avec orgId et org: nom de l'organisation>,trace:null,orgId}`. **Aucune mutation**, aucun effet sur les parties qui ne sont pas en monde vivant (elles gardent exactement le comportement actuel : test d'identité).
2. `mgmt-ecran-classements.js` (`mgmtClassementsRowHtml`, ~ligne 113-121) : l'organisation d'une ligne issue de `m.orgs` est le nom de **son** organisation (aujourd'hui le nom de Split est affiché ou rien) ; un combattant de `m` garde le nom de la partie.
3. Les autres lecteurs de `mgmtFicheLigne` (`grep -n mgmtFicheLigne *.js`) : vérifie que chacun se comporte correctement avec une ligne d'organisation vivante (nom, catégorie, palmarès) ; corrige ceux qui supposent `trace` ou `m.roster` ; ne touche pas les autres.
4. Les blocs « champions » des classements/ceintures qui lisent `m.exterieur` seulement : en monde vivant ils lisent aussi `m.orgs` (même fonction, pas de second système).
