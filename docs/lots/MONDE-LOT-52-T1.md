# Monde lot 52 T1 — la compression de la sauvegarde du mode management

Branche : `compression-sauvegarde` (la branche courante de ce dossier ; commits ICI ; le superviseur fusionne). **Contexte et urgence.** Une sauvegarde de partie neuve pèse **1 899 979 octets** (mesure de `tests/mgmtReleveReduit.test.js` : `bytes`), soit **21 octets sous le plafond de 1 900 000** que le projet s'impose (localStorage ~5 Mo ; la sauvegarde et son secours sont écrites deux fois). Toute nouvelle donnée écrite dans les six ans de passé généré d'avance fait dépasser le plafond : les lots récents ont dû exclure le passé de leurs écritures. **La compression a été acceptée par Anthony** (« une tranche séparée de compression de la sauvegarde, pour monter le plafond ; IndexedDB écarté : le code de sauvegarde est synchrone »). Aucune dépendance (`vanilla JS`, pas de bibliothèque : tu écris l'algorithme toi-même), **100 % synchrone**, jamais `import`/`export`, `"use strict";`.

Lis d'abord : `mgmt-save.js` (`saveMgmt`, `loadMgmt`, `mgmtSerialiser`, `mgmtDeserialiser` ou équivalents, `MGMT_KEY`, `MGMT_BACKUP_KEY`, `stockageLire`/`stockageEcrire` : trouve les vrais noms), `mgmt-emplacements.js` (les emplacements de sauvegarde), `tests/mgmtReleveReduit.test.js` (la mesure de poids), `tests/mgmtSauvegarde*.test.js` (les tests de sauvegarde existants), `mgmt-passe.js` (`m.passe.archive` : les tables de chaînes qui allègent déjà le passé).
